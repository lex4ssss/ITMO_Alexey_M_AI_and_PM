# Автоматизация обработки тикетов поддержки

AI/ML-система для крупного онлайн-сервиса: 5 млн активных пользователей, 200 тыс. тикетов в сутки,
всплески до 10–20 тыс. за 10 минут. Классифицирует обращение, маскирует персональные данные,
находит релевантные фрагменты базы знаний, готовит ответ и решает, кому его отдать:
пользователю, оператору или в очередь инцидента.

Ключевое решение: **автоматическое действие разрешено только там, где ошибка обратима**.
Возвраты денег и удаление аккаунта не закрываются автоматически ни при какой уверенности модели.
При недоступности LLM система эскалирует на человека и не замолкает.

## Зачем это бизнесу

40% потока это типовые повторяющиеся обращения, на которые оператор пишет один и тот же ответ,
и рутина съедает время, которого не хватает на сложные случаи. MVP закрывает без оператора
около 12–13% всего потока и сокращает время обработки ещё на трети за счёт готовых черновиков.
При стоимости обработки 150 ₽ за тикет это порядка 2.3 млрд ₽ в год; расчёт с явными допущениями
и анализом чувствительности лежит в [docs/product.md](docs/product.md).
Слабое место расчёта продуктовое, а не техническое: если доля возвратов тикета вырастет
с текущих 9% до 60%, автоматизация перестанет окупаться, поэтому reopen rate вынесен
в стоп-метрику пилота.

## Как запустить PoC

```bash
# Python 3.9+
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python poc/data/make_dataset.py
python poc/run_demo.py
pytest -q
```

Проверить деградацию при недоступности LLM отдельно:

```bash
LLM_FORCE_FAIL=1 python poc/run_demo.py
```

## Что демонстрирует PoC

`python poc/run_demo.py` прогоняет шесть сценариев, все запускаются одной командой:

| Сценарий | Что показывает |
|---|---|
| **happy path** — «забыл пароль» | безопасная категория, уверенность 0.91 → автоответ пользователю с опорой на базу знаний |
| **borderline** — то же с контактами в тексте | уверенность 0.72 ниже порога 0.75 → черновик оператору, автоответ не уходит |
| **risky path** — «верните деньги за заказ» | категория запрещена к автозакрытию → оператор, ответ пользователю не уходит |
| **low confidence** — бессвязный текст | уверенность 0.39 → оператор без попытки генерации |
| **incident mode** — «сайт не открывается» | подтверждение приёма и привязка к инциденту вместо индивидуального ответа |
| **fallback** — LLM недоступен | та же безопасная категория деградирует в эскалацию оператору |

Сценарий из условия задания реализован целиком: на вход подаётся mock-тикет (1) → определяется
тема и риск (2) → находится релевантный фрагмент базы знаний (3) → готовится черновик ответа
или маршрут (4) → решение пишется в `poc/decisions.jsonl` (5) → рискованный и low-confidence
случаи уходят оператору и автоматически не закрываются (6).

Во всех сценариях персональные данные маскируются до классификации и до записи в журнал:
в логах остаётся `<EMAIL>`, `<PHONE>`, `<CARD>`. Каждое решение пишется в `poc/decisions.jsonl`
с категорией, уверенностью, источником решения, использованными статьями и латентностью.

## Что реально работает, а что спроектировано

**Реализовано в коде:** редакция PII на регулярных выражениях; классификатор на символьных
n-граммах и логистической регрессии (7 категорий, macro-F1 0.983 на кросс-валидации по
синтетическим данным); поиск по базе знаний на TF-IDF; политика решений с двумя порогами
уверенности и списком запрещённых к автоматизации категорий; деградация при отказе LLM;
режим инцидента; журнал решений; 12 тестов.

**Спроектировано, но не реализовано:** очередь между быстрым и медленным путями, векторное
хранилище, Safety Filter, интерфейс оператора, детектор инцидентов как сервис (в PoC это флаг),
реальный LLM-провайдер (в PoC стоит mock с управляемым отказом).

## Допущения и ограничения

- Данные синтетические: 182 тикета из шаблонов. Качество классификатора на них не переносится
  на реальный поток: цифра показывает работоспособность пайплайна, будущую точность
  по ней предсказать нельзя.
- LLM заменён mock-генератором: он собирает ответ из найденного фрагмента базы знаний.
  Это позволяет проверить контракт и путь отказа без ключа и интернета.
- Пороги 0.45 и 0.75 выбраны как разумные стартовые, по данным их никто не подбирал.
  На реальных данных они подбираются по кривой «доля автоматизации против доли ошибок»
  и требуют калибровки вероятностей.
- Латентность измерена локально на одном процессе, без сети и конкуренции за ресурсы.
