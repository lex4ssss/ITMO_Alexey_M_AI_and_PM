# ML и LLM: что чем решается

## Разделение по типам задач

| Задача | Подход | Почему так |
|---|---|---|
| Редакция PII | правила (регулярные выражения) | детерминированность важнее полноты; ошибка модели здесь означает утечку персональных данных во внешний API, а правило проверяется тестом |
| Жёсткие категории (возврат, удаление аккаунта) | правила поверх модели | цена пропуска несимметрична: лучше лишний раз отдать оператору, чем автоматически закрыть заявку на возврат денег |
| Классификация темы | классический ML: TF-IDF + линейная модель | категорий десятки, разметка дешёвая, инференс единицы миллисекунд при бюджете 500 мс; LLM здесь дороже в 100 раз без выигрыша в качестве |
| Оценка риска и маршрут | правила поверх категории | политика должна быть читаемой, аудируемой и меняться без переобучения |
| Поиск похожих тикетов и статей | embeddings + гибридный поиск | нужна семантическая близость, а не совпадение слов; BM25 добавляется, потому что на редких терминах и артикулах он точнее |
| Генерация ответа | LLM с контекстом из retrieval | единственная задача, где нужна свободная формулировка на естественном языке |
| Суммаризация для оператора | LLM | экономит время чтения длинной переписки |
| Дедупликация на всплесках | хеш + эмбеддинги | схлопывание однотипных обращений в один инцидент дешевле, чем генерация ответа на каждое |

## Где LLM использовать не стоит

- В синхронном пути маршрутизации: не укладывается в 500 мс и создаёт зависимость SLA от внешнего провайдера.
- Для принятия решения о возврате денег или удалении аккаунта: цена ошибки несоразмерна.
- Для извлечения структурированных полей, где есть регулярное выражение или справочник.
- Как единственный классификатор без калибровки: у LLM нет честной оценки уверенности,
  а политика эскалации построена именно на пороге уверенности.

## Классификатор: baseline и путь развития

Baseline, который разумно запустить первым и который реализован в PoC:
символьные n-граммы (`char_wb`, 3–5) + логистическая регрессия с балансировкой классов.
Символьные n-граммы выбраны из-за русской морфологии, опечаток и обращений в верхнем регистре —
словарные униграммы на таком входе рассыпаются.

Следующие шаги по возрастанию стоимости: добавить метаданные (канал, длина, время суток,
история пользователя) → заменить TF-IDF на fine-tuned rubert-tiny → добавить иерархию
категория/подкатегория. Переход на трансформер оправдан только если он даёт прирост macro-F1
больше 3 п.п. при латентности в пределах бюджета.

## Откуда берутся модели

- Классификатор — обучается внутри на исторических тикетах. Разметка: год закрытых обращений,
  где категория уже проставлена оператором вручную в CRM; это готовая разметка без затрат
  на разметчиков, но с шумом, потому что операторы ставят категорию небрежно.
  Перед обучением — ручная перепроверка стратифицированной выборки 2000 тикетов для оценки
  качества самой разметки.
- Эмбеддинги — открытая мультиязычная модель (например, семейства `e5` или `rubert`),
  дообучение на своих парах «вопрос — статья» на втором этапе.
- LLM — внешний провайдер по API либо self-hosted открытая модель.
  Выбор решается стоимостью и требованием не отправлять данные наружу; архитектура
  от конкретного провайдера не зависит, вызов изолирован за интерфейсом генератора.

## Данные

Нужны: год исторических тикетов с категориями и итоговыми ответами, база знаний и FAQ,
логи операторских правок, флаги reopen и CSAT по тикету.
Отдельно — размеченный набор «безопасно ли автозакрывать» на 3–5 тысячах тикетов;
именно он определяет пороги политики, и его нельзя вывести из существующей разметки.

## Как валидируется качество

- Классификатор: стратифицированная кросс-валидация по 5 фолдам, метрика macro-F1
  (классы несбалансированы, важны редкие). Отдельно смотрится recall по рискованным категориям —
  он должен быть близок к 1, потому что пропуск здесь дороже ложной тревоги.
- Разделение по времени: валидация на более поздних тикетах, чем обучение, иначе оценка завышается
  сезонностью и волнами однотипных обращений.
- Генерация: офлайн — доля ответов, опирающихся на найденный фрагмент (groundedness),
  оценка LLM-судьёй с ручной перепроверкой части выборки; онлайн — доля черновиков,
  отправленных оператором без правок, reopen rate и CSAT.
- Обязательный этап shadow mode: модель работает на реальном потоке, ничего не отправляя,
  решения сравниваются с действиями операторов.

Текущее качество PoC-классификатора на синтетических данных: macro-F1 0.983 при
кросс-валидации на 5 фолдов, 182 примера, 7 категорий. Число синтетическое и не переносится
на реальные данные — оно показывает работоспособность пайплайна, а не будущее качество.

## Обработка низкой уверенности

Два порога вместо одного: ниже 0.45 — сразу оператору без генерации; между 0.45 и 0.75 —
режим черновика; выше 0.75 и безопасная категория — автоответ.
Пороги подбираются по кривой «доля автоматизации против доли ошибок» на отложенной выборке
и пересматриваются после каждого переобучения, потому что калибровка модели меняется.
Вероятности калибруются (Platt scaling или изотоническая регрессия) — без калибровки
порог 0.75 не означает 75% точности и политика становится неуправляемой.
